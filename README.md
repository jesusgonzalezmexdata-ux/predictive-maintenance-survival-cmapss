# MULTIAGENTS MASTER v2 — Intent-Driven MDA Governance Kernel

This repository is a **master bootstrap system for building AI-assisted projects from human intent**. It is not a product template and it is not tied to any AI vendor.

A human can place a Markdown file containing a project's vision/objective in `intake/`, or explicitly ingest a Markdown file located in a future product/domain folder. The kernel normalizes that intent, exposes missing decisions, selects a language-agnostic architecture profile, declares governed scopes, generates local contracts/specification/work packages, compiles tool adapters, and leaves the repository ready for governed implementation.

## North-star invariant

```text
HUMAN INTENT
    ↓
NORMALIZED CONTRACT
    ↓
ARCHITECTURE
    ↓
GOVERNED SCOPES
    ↓
SPEC / TASKS
    ↓
AGENT EXECUTION
    ↓
DETERMINISTIC VERIFICATION
    ↓
EVIDENCE / PROMOTION
```

The intake layer may scaffold architecture. It **never grants unbounded authority to generate product code**.

## Core invariants

- `CORE_CONTRACT != TOOL_ADAPTER`
- `HUMAN_INTENT_PRECEDES_GENERATED_ARCHITECTURE`
- `MISSING_SEMANTICS_MUST_SURFACE_AS_DECISIONS`
- `INTAKE_MAY_SCAFFOLD_BUT_NOT_IMPLEMENT_PRODUCT`
- `DETERMINISTIC_EVIDENCE_OVER_AGENT_CLAIMS`
- `NO_SELF_PROMOTION_OF_AUTHORITY`

If a future agent lacks hooks, subagents or native sandboxing, those guarantees are provided externally through `repoctl`, Git/CI gates, wrappers, proxies or OS/container isolation.

## Fastest workflow: drop a Markdown objective

1. Copy `intake/OBJECTIVE_TEMPLATE.md` to `intake/my-project.md`.
2. Replace the template content with your real vision, objective and any known constraints.
3. Run:

```bash
python .scripts/repoctl.py reconcile-intake
```

The repository will create:

```text
docs/intents/INTENT-XXXXXXXXXXXX/
├── INTENT_CONTRACT.json
├── ARCHITECTURE_PROPOSAL.md
├── BOOTSTRAP_SPEC.md
├── DECISIONS_REQUIRED.md
└── WORK_PACKAGE.json
```

It will also declare the applicable product scopes in canonical MDA and generate a local `AGENTS.md` + `SCOPE_STATE.json` for every newly materialized scope.

No application implementation is generated by this step.

## Use a Markdown file in any future folder

A file outside `intake/` can be ingested explicitly:

```bash
python .scripts/repoctl.py ingest path/to/OBJECTIVE.md
```

Or mark a Markdown file for automatic discovery:

```text
MDA-Intent: true
```

Then run `reconcile-intake`.

## Minimal intent file

Only a title plus an objective or vision are required to normalize intent:

```markdown
# My Project

MDA-Intent: true
Intent-Type: PROJECT
Project-Kind: DATA_SCIENCE

## Vision
Turn manufacturing data into traceable quality evidence.

## Objective
Create the governed architecture needed to ingest, validate, model and report results reproducibly.
```

Additional sections such as Constraints, Deliverables, Acceptance Criteria and Non-Goals make the generated architecture more precise. Missing semantics are recorded rather than invented.

## Project kinds / scaffold profiles

Built-in profiles are `GENERIC`, `DATA_SCIENCE`, `API`, `CLI`, `WEB_APP`, `LIBRARY`, `RESEARCH` and `INFRASTRUCTURE`. These profiles define topology only; they do not force a framework or programming language.

## Agent onboarding

Any new agent should begin with:

```bash
python .scripts/repoctl.py inspect
python .scripts/repoctl.py preflight --path <target>
python .scripts/repoctl.py context <target>
```

Then it follows root + nearest local contracts. Tool-specific adapters are generated from `.mda/`; they are never the source of truth.

## Deterministic interface

```text
repoctl inspect
repoctl discover-intents
repoctl ingest <file.md>
repoctl reconcile-intake
repoctl preflight --path <target>
repoctl context <target>
repoctl compile
repoctl verify
repoctl security-scan
repoctl audit-verify
repoctl scheduled <job>
repoctl declare-scope ...
repoctl propose-scope ...
```

A local event-style watcher is also provided:

```bash
python .scripts/watch_intake.py
```

Writing an intent into the owner-controlled `intake/` inbox plus running the watcher/reconciler is the low-friction architecture-generation path.

## Greenfield behavior

Architecture scaffolding does **not** turn an empty repository into brownfield implementation. Generated `AGENTS.md`, `SCOPE_STATE.json`, normalized intents, specs and architecture proposals are declarative artifacts. `PROJECT_STATE` changes to `BROWNFIELD` only when substantive product content appears.

All 19 capabilities remain represented. P01–P15 and P19 form the governed operating system according to maturity; P16 Shadow Simulation, P17 Federation and P18 Economic Agency remain explicitly gated until their required maturity is promoted.
